## 一、WheelEvent 核心属性速览

所有滚动设备都通过 `wheel` 事件暴露以下核心属性：

| 属性                                         | 类型                    | 说明                                            |
| -------------------------------------------- | ----------------------- | ----------------------------------------------- |
| `deltaX` / `deltaY` / `deltaZ`               | `double`                | 各方向的滚动量                                  |
| `deltaMode`                                  | `unsigned long`         | 滚动量的单位：`0x00`=像素，`0x01`=行，`0x02`=页 |
| `wheelDelta` / `wheelDeltaX` / `wheelDeltaY` | `int`（已弃用，非标准） | 旧版接口，值为整数                              |

**关键注意事项**：

1. `wheel` 事件 ≠ `scroll` 事件——`wheel` 不一定触发滚动，滚动也不一定由 `wheel` 触发。

2. `delta*` 值**不一定反映内容的实际滚动方向**，不应依赖它判断滚动方向。

3. **必须优先读取 `deltaMode` 再解析 `deltaY`**。不同浏览器对同一设备的单位映射存在差异，不可假设 `deltaY` 的单位一定为像素。

4. `deltaY` 的绝对值深受操作系统“滚动速度/行数”设置的影响，以下数值均为典型默认值，实际工程中需结合相对特征综合判断。

## 二、A 类：传统鼠标滚轮（离散单次型）

### 2.1 事件特征

| 特征维度               | 具体表现                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| **deltaMode**          | 因浏览器而异（详见 2.2）                                                                           |
| **deltaY 数值类型**    | 多数为整数，但 macOS 平滑滚动下可为浮点数（详见 2.4）                                              |
| **单次事件典型绝对值** | **较大**，典型默认值约 **100~125 像素**，或 **1~3 行**（受系统滚动速度设置影响，可浮动至 10~200+） |
| **事件间隔**           | 两次操作间隔 **> 10ms**（多数情况下 > 16ms，受机械棘轮结构限制）                                   |
| **事件数量**           | 一次物理操作产生 **1 个** `wheel` 事件（或极稀疏的多个）                                           |

### 2.2 浏览器对 deltaMode 的差异

各浏览器对底层滚动数据的映射存在显著差异：

| 浏览器                     | deltaMode 典型行为                                                       |
| -------------------------- | ------------------------------------------------------------------------ |
| **Firefox**                | 传统鼠标滚轮默认使用 `DOM_DELTA_LINE`（0x01）或 `DOM_DELTA_PAGE`（0x02） |
| **Chrome / Edge / Safari** | 几乎总是使用 `DOM_DELTA_PIXEL`（0x00），即使接入传统鼠标                 |

> **工程要点**：`DOM_DELTA_LINE`（0x01）和 `DOM_DELTA_PAGE`（0x02）**仅在 Firefox 中常见**。若在 Chrome/Edge/Safari 中检测到这两种模式，属于极少数例外情况，仍需结合后续特征综合判定。

### 2.3 典型场景

- 普通办公鼠标（罗技 M 系列、微软基础鼠标等）
- 键盘模拟的滚动操作（PageUp/PageDown 键映射）
- 棘轮模式下**低速转动**时（如自由滚轮在 SmartShift 低速时自动切回棘轮模式），每次物理棘轮卡位产生一个孤立事件

### 2.4 ⚠️ 平台特异性例外（重要）

**macOS 平滑滚动（Smooth Scrolling）**：当 macOS 系统设置中开启该功能（默认开启）时，即使插着普通传统鼠标，系统也会将滚轮的离散步进**插值**为连续的**浮点数**（如 `1.2`、`3.7`）。

- **后果**：此时 A 类鼠标的 `deltaY` 也会含浮点数，若仅凭“浮点数”判定，会将其误判为 C 类触摸板。
- **区分对策**：必须结合**事件间隔**。A 类鼠标受物理棘轮限制，即使携带浮点数，事件间隔也 **> 16ms**；而 C 类触摸板主动拖拽时，事件间隔稳定在 **≤ 16ms**（与屏幕刷新率同步）。

## 三、B 类：高精度滚轮（离散密集簇型）

### 3.1 事件特征

| 特征维度            | 具体表现                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **deltaMode**       | 几乎全为 `DOM_DELTA_PIXEL`（0x00）                                                                                                                 |
| **deltaY 数值类型** | **整数**（固定小值）                                                                                                                               |
| **单次事件绝对值**  | **较小且极度稳定**，典型值如 **15、20、30**（具体数值因操作系统、驱动及鼠标型号而异，但**簇内数值恒定**；个别平台存在整格 120 上报的情况，见 3.2） |
| **事件间隔**        | **极短**，簇内通常 **< 5ms**                                                                                                                       |
| **事件数量**        | 一次物理滚动咔哒产生 **多个**（如 6~8 个）事件，呈密集爆发状                                                                                       |
| **簇内数值稳定性**  | 每个事件的 `deltaY` **数值几乎恒定**（如全为 15 或全为 20）                                                                                        |

### 3.2 工作原理与数值说明

高精度滚轮的分辨率远高于传统滚轮：**轮体每旋转一定角度**就会向系统报告一个离散事件（事件由“滚动距离”驱动，而非由物理滚动咔哒触发）。在棘轮模式下，一次物理滚动咔哒恰好对应一个步进刻度，其位移通常被拆分为**多个离散事件**来上报。

> **补充**：此类设备（如罗技 MX Master 系列）一般可在“棘轮模式”与“无级（自由滚轮）模式”间切换。关闭棘轮反馈后，滚轮没有物理刻度、可连续自由转动，事件随转动距离持续产生。

**关于 `deltaY` 数值的平台差异**：

| 平台/驱动                     | 单子事件典型值 | 每咔哒事件数 | 总位移     |
| ----------------------------- | -------------- | ------------ | ---------- |
| Windows（`WHEEL_DELTA` 拆分） | 15~20          | 6~8          | ≈ 120      |
| Linux（libinput）             | 15 或 120      | 1~8          | 视驱动而定 |
| macOS（高精度模式）           | 视驱动而定     | 视驱动而定   | 视驱动而定 |

> **结论**：B 类的核心特征并非“数值等于 15”，而是 **“每次物理操作产生多个数值恒定的事件”**。判定时应聚焦于簇内数值的恒定性，而非具体数值大小。

### 3.3 典型设备

- 罗技 MX Master 系列（棘轮/分段模式）
- 罗技 G 系列游戏鼠标
- 任何支持“高分辨率滚动”（High-resolution scrolling）的鼠标

### 3.4 工程陷阱

若将 B 类误判为 C 类（连续流），会导致一次咔哒触发一次“跟手拖拽”而非“瞬翻”；若误判为 A 类（离散单次），则每个子事件都会触发翻页，导致一次咔哒翻 6~7 页。**精确区分 B 类与 A/C 类是滚动适配的核心难点**。

## 四、C 类：触摸板 / 轨迹球（连续流型）

### 4.1 事件特征

| 特征维度            | 具体表现                                                                    |
| ------------------- | --------------------------------------------------------------------------- |
| **deltaMode**       | 几乎全为 `DOM_DELTA_PIXEL`（0x00）                                          |
| **deltaY 数值类型** | **通常为浮点数**（如 0.5、1.2、-3.7），但特定驱动下也可能为小整数（见 4.3） |
| **单次事件绝对值**  | 动态可变，通常较小，与手指移动速度正相关                                    |
| **事件间隔**        | **高频连续**，主动拖拽时稳定 **≤ 16ms**（与显示刷新率同步）                 |
| **事件数量**        | 持续产生，直到手指离开                                                      |
| **数值变化特征**    | 数值连续变化，**变异性大**（随速度增减）                                    |

### 4.2 惯性阶段特征

触摸板最重要的特征是**系统惯性阶段**（手指离开后自动减速滚动）：

| 特征维度            | 主动拖拽阶段     | 惯性阶段                         |
| ------------------- | ---------------- | -------------------------------- |
| **触发条件**        | 手指接触触摸板   | 手指已离开                       |
| **deltaY 变化趋势** | 随手指速度变化   | **持续衰减**（绝对值逐渐减小）   |
| **事件间隔**        | 稳定 ≤ 16ms      | **逐渐增大**（可能超过 20ms）    |
| **即时速度**        | 可变（可快可慢） | **持续降低**，低于主动拖拽的下限 |

**关于惯性检测的平台差异**：

| 平台                         | 惯性检测方式                                                                                                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **macOS（WebKit）**          | 可通过 `event.phase` 和 `event.momentumPhase` 等非标准属性检测惯性阶段；`phase` 在手指离开后变为 `none`，`momentumPhase` 开始指示惯性状态（`began`/`changed`/`ended`） |
| **Windows / Linux / 跨平台** | 目前 W3C 规范中**没有标准属性**标记惯性事件，开发者只能通过 `deltaY` 的数值变化模式**推测**是否进入惯性阶段                                                            |

> **工程要点**：在 macOS 平台上，应优先使用 `phase`/`momentumPhase` 进行惯性检测；跨平台场景下仍需依赖数值模式推测。

### 4.3 特殊情况：输出整数的触摸板与决策修正

并非所有触摸板都输出浮点数。部分 Windows 触摸板在特定驱动下可能输出**整数**（如 1、2、3）。这会导致与 B 类（高精度滚轮）的特征高度重叠，是区分的最大难点。

**修正后的启发式判定规则（按权重排序）**：

1. **含浮点数 + 间隔 ≤ 16ms** → 几乎可确定为 C 类（触摸板）。_（注：macOS 平滑滚动的鼠标也含浮点数，但间隔 > 16ms，需靠间隔二次过滤）_
2. **全为整数 + 持续大量涌现（持续数百毫秒以上） + 数值动态变化（如 1,2,1,3,2）** → 更可能是 C 类（触摸板）而非 B 类。
3. **全为整数 + 数值固定（全为 15 或全为 20）+ 呈短簇爆发（< 50ms 内结束）** → 更可能是 B 类（高精度滚轮）。

**⚠️ macOS 平台特例**：在 macOS 上，触摸板通常通过 `phase` 属性直接标识，故上述基于数值类型的判定规则主要适用于 Windows/Linux 平台。

### 4.4 典型设备

- MacBook 触控板
- Windows Precision Touchpad
- 苹果 Magic Trackpad
- 部分轨迹球设备

## 五、总结对比表

| 特征                     |                A 类（传统滚轮）                |            B 类（高精度滚轮）             |               C 类（触摸板）                |
| ------------------------ | :--------------------------------------------: | :---------------------------------------: | :-----------------------------------------: |
| `deltaMode`              | Firefox 下多为 LINE/PAGE；其他浏览器多为 PIXEL |                   PIXEL                   |                    PIXEL                    |
| `deltaY` 常见类型        |          整数（macOS 平滑下可为浮点）          |            **整数（固定值）**             |         **浮点数**（偶为动态整数）          |
| 单次 `\|deltaY\|` 典型值 |        **较大**（100~125，受系统影响）         | **较小且恒定**（如 15/20/30，因平台而异） |           **动态可变**，通常 < 40           |
| 事件间隔                 |            **> 10ms**（通常 >16ms）            |             **< 5ms**（簇内）             |             **≤ 16ms**（持续）              |
| 每操作事件数             |                **1 个（孤立）**                |            **多个（密集簇）**             |         **持续流（直至手指离开）**          |
| 数值变异性               |                 不适用（单次）                 |             **极低（恒定）**              |             **高（连续变化）**              |
| 惯性阶段                 |                       无                       |                    无                     | **有（衰减特征；macOS 可通过 phase 检测）** |

## 六、关键工程启示与判定优先级

### 6.1 浏览器不提供设备类型标识

目前没有任何标准 API 能直接区分 `wheel` 事件来自鼠标滚轮还是触摸板。开发者需要通过多维度特征综合判定。

### 6.2 deltaMode 判定规则

- 若 `deltaMode` 为 `DOM_DELTA_LINE`（0x01）或 `DOM_DELTA_PAGE`（0x02）：
  - **在 Firefox 中**：直接归类为 A 类（传统滚轮）。
  - **在其他浏览器中**：此情况极少见，仍需结合后续特征综合判定，不可直接定论。
- 若 `deltaMode` 为 `DOM_DELTA_PIXEL`（0x00）：继续执行后续判定流程。

### 6.3 缩放行为处理

任何自定义滚动逻辑的开头，必须检查 `event.ctrlKey` 或 `event.metaKey`（macOS）是否为 `true`。

> **⚠️ 重要警告**：在触摸板上，**双指捏合缩放（pinch-to-zoom）同样会触发 `wheel` 事件**，且 `event.ctrlKey` 可能为 `true`。简单拦截所有带修饰键的事件会**破坏用户的捏合缩放操作**。

**推荐做法**：

- 若你的组件**不支持缩放**，可以直接 `return` 或 `preventDefault()`，将事件交由浏览器处理或忽略。
- 若你的组件**支持缩放**，应区分“缩放意图”和“滚动意图”：
  - 缩放场景下，通常 `event.ctrlKey` 为 `true` 且 `deltaY` 绝对值较小、连续变化。
  - 滚动场景下，则按本文档的三类设备判定逻辑处理。
- 当不确定时，**让浏览器处理默认行为**是最安全的选择。

### 6.4 浮点数判定需结合平台

`deltaY` 含浮点数在 Windows 上是 C 类的强信号，但在 **macOS** 中需检查事件间隔。若间隔 > 16ms，则仍属于 A 类（平滑滚动开启的传统鼠标）。在 macOS 上，应优先检查是否存在 `phase`/`momentumPhase` 属性。

### 6.5 小整数模糊地带的决断流程（B 类 vs C 类）

若 `deltaY` 为小整数（如 15）：

- 观察**事件间隔**：< 5ms 且呈短簇爆发 → B 类；
- 观察**数值变异性**：持续数百毫秒且数值动态变化（如 1,2,3,2）→ C 类；
- **macOS 平台**：优先检查 `phase` 属性，有 `phase` 则属触摸板交互。

### 6.6 惯性检测策略

- **macOS 平台**：优先使用 `event.phase` 和 `event.momentumPhase` 检测惯性阶段。
- **跨平台场景**：由于缺乏标准 API，惯性阶段需通过 `deltaY` 衰减趋势、事件间隔增大、即时速度下降等特征综合判定。
