# 滚动设备判定决策

> 记录阅读器中「判断滚动设备」的判定规则与相关决策。
> 设备特征等通用知识见 [滚动设备特征.md](./滚动设备特征.md)；本文档只记录判定逻辑本身，不与具体代码实现挂钩。

### 1. 不用「事件间隔」判定

A/B 类设备在快速滚动时，滚动事件触发间隔可能反而会比 C 类更短（因为C类的滚动事件是模拟上报的所以会有固定的最小间隔）。事件间隔是和**滚动速度相关**而非和设备相关，不能作为判定依据。

### 2. 用「成整数倍」判断A/B类

A/B 类每次上报的滚动量是固定值，只会在滚动速度快时进行事件合并，变成固定值的倍数。
而 C 类很难滚动出固定整数倍的滚动量。

### 3. 过滤小值的「成整数倍」判断

C 类在「缓慢滚动」或「惯性模拟」阶段上报的滚动量会很小，导致更加容易出现「相同」和「成整数倍」的情况。因此在判定时需要在滚动量小于阈值时停止「成整数倍」的判断。

### 4. 判定方向的不对称

误判为 A/B 类的代价是**误翻页**（严重）；误判为 C 类的代价只是**轻微抖动**。因此，在当前已经判定设备类型是 C 类时，需要经过严格的判定后才能切换成 A/B 类。而反过来，从 A/B 类切换到 C 类时，可以放松判定条件。

### 5. 动态判定，不做「锁定 + 定时重置」

- 判定本身开销极低，无性能瓶颈，无需节流；
- 定时重置会破坏 B 类的**缓慢滚动**（事件间隔可能超过重置时限，永远凑不够成倍计数）；
- 因此判定基准（上次滚动量）**永不按时间重置**，成倍计数只由"小值 / 不成倍"清零。

### 6. 过小滚动量判 C 类

只有 C 类会出现过小的滚动量。
