# 新增多选模式适配

## 前置判断：是否真的需要多选适配

多选加载是站点适配之上的**额外能力**，需要用户能自选要加载的内容时才需要新增多选适配，目前只有两种场景：

- **选择多个作品合并加载**：在列表页勾选多个作品，把所有作品的页按顺序合并成一本阅读（pixiv、kemono）
- **选择一个作品里的指定页**：在缩略图页勾选要加载的页，只加载这些页（ehentai）

多选适配**必须建立在已有站点适配之上**（页面已通过 `setup()` / `setupSiteAdapter()` 接入、且能在 handler 里拿到 `coreCtx`）。

## 两种多选模式

两种模式在实现上是同一套机制，区别只在于**可选项的粒度**：

| 模式           | 支持站点      | 可选项粒度 | `getImgList` 返回值    |
| -------------- | ------------- | ---------- | ---------------------- |
| 多作品合并加载 | pixiv、kemono | 一个作品   | 整本作品的所有页       |
| 单作品选页加载 | ehentai       | 一页       | 单页 `[{ src, name }]` |

## 实现方式

核心是 [src/userscript/multiSelect/useMultiSelectLoad.tsx](../../src/userscript/multiSelect/useMultiSelectLoad.tsx) 导出的 `useMultiSelectLoad`。它把两种模式统一成同一个模型：**每个「可选项」有一个 id，站点提供 `getImgList(id)` 拿到该可选项的图片列表，确认加载后按选择顺序把所有列表合并成一条**。

从 `src/site/` 下按相对路径导入即可（`userscript/multiSelect` 不是独立打包模块，会内联进站点模块）：

```ts
import { useMultiSelectLoad } from '../userscript/multiSelect';
```

站点只需要做 3 件事：

1. 调用 `useMultiSelectLoad(coreCtx, options)` 传入可选项如何取图
2. 调用 `ms.registerItems(id, fillItems)` 注册页面中可选项的 DOM → id 映射（遮罩会盖在这些 DOM 上）
3. 返回 `ms.createCleanup(id)` 作为页面清理函数

其余能力（FAB 多选按钮、快捷键、ESC 退出、选中状态缓存、懒加载合并）都由 `useMultiSelectLoad` 自动完成。

### 示例一：选择多个作品合并加载（pixiv 式）

可选项 = 一个作品，`getImgList` 返回整本作品的页。参考 [src/site/pixiv.tsx](../../src/site/pixiv.tsx)、[src/site/kemono.tsx](../../src/site/kemono.tsx)。

```ts
list: async (coreCtx, { id }) => {
  const { options } = coreCtx;

  const ms = await useMultiSelectLoad(coreCtx, {
    id, // 列表唯一标识，用于区分不同列表的选择缓存
    getImgList: async (workId) => {
      const res = await request<{
        body: { urls: { original: string; regular: string } }[];
      }>(`/ajax/illust/${workId}/pages`, { responseType: 'json' });
      return options.load_original_image
        ? res.response.body.map((img) => img.urls.original)
        : res.response.body.map((img) => img.urls.regular);
    },
  });

  await ms.registerItems(id, async (map) => {
    for (const dom of await waitDom('li div[data-worktype="illusts"]'))
      map.set(dom, dom.dataset.workid!);
  });

  return ms.createCleanup(id);
},
```

### 示例二：选择一个作品里的指定页（ehentai 式）

可选项 = 一页，`getImgList` 只返回单页；用 `allItemIds` 提供全部可选项 id。参考 [src/site/ehentai/multiSelectLoad.tsx](../../src/site/ehentai/multiSelectLoad.tsx)。

```ts
const ms = await useMultiSelectLoad(coreCtx, {
  id: pageCtx.galleryId,
  allItemIds: () => range(pageCtx.imgNum).map(String), // 全部页索引
  getImgList: async (id) => {
    const i = Number(id);
    await ensureImgPageUrl(pageCtx, i);
    pageCtx.imgList[i] ||= await getImgUrl(pageCtx, i);
    return [{ src: pageCtx.imgList[i], name: pageCtx.fileNameList[i] }];
  },
});

await ms.registerItems(pageCtx.galleryId, (map) => {
  for (const dom of querySelectorAll<HTMLAnchorElement>('#gdt a')) {
    const imgIndex = Number(/(?<=-)\d+(?:\?|$)/.exec(dom.href)?.[0]) - 1;
    if (!Number.isNaN(imgIndex))
      map.set(dom.querySelector('[title]')!, String(imgIndex));
  }
});
```

## 参数说明

`useMultiSelectLoad(coreCtx, options)` 的 `options`：

| 参数             | 说明                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| `id`             | 当前列表的唯一标识，用于区分不同列表的选择缓存                                                                |
| `getImgList(id)` | 根据可选项 id 返回其图片列表，元素约定与站点适配的 `getImgList` 相同（url 字符串或 `{ src, width, height }`） |
| `allItemIds?`    | 返回所有可选项 id 的函数。提供时，「未选择直接进入阅读」会加载全部可选项；不提供时进入阅读必须经过多选确认    |
| `onStart?`       | 第一次进入多选模式时对页面 DOM 的预处理（如设置 `position: relative`），返回清理函数                          |

`ms` 控制器常用方法：

| 方法                                         | 说明                                                                                                                                |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `registerItems(id, fillItems, maxWaitTime?)` | 注册可选项 DOM → id 映射；会等待到页面 DOM 更新（与上次注册的不同），超时（默认 5s）抛错；注册后若有 pending 缓存会自动恢复选中状态 |
| `createCleanup(id)`                          | 返回页面切换时的清理函数：同一列表翻页只卸载遮罩、保留实例和选中；切换到不同页面时完全清理                                          |
| `setSelectedIds(ids)`                        | 程序化设置选中项（如 ehentai 的「Shift + 点击输入页码范围」）                                                                       |
| `selectedIds()` / `isEnabled()` / `load`     | 当前选中项 / 是否处于多选模式 / 触发多选加载（进阅读）                                                                              |

## 注意事项

- 遮罩 `SelectionMask` 是绝对定位的，可选项 DOM 需要是定位元素（`position: relative`）。可以用 `onStart` 设置（参考 kemono），或直接加 CSS（参考 ehentai）
- FAB 多选按钮和快捷键（`Shift + v` 进入/确认多选、`v` 确认加载）由 `useMultiSelectLoad` 自动注册，站点无需处理
- 不传 `allItemIds` 时，注入的 `getImgList` 会带 `type: 'multiSelect'` 标记，使 `canLoadComic()` 为 false，此时 `v`（进入阅读模式）会先走多选确认流程；传了 `allItemIds`（如 ehentai）则不带标记，`v` 直接进入阅读模式（默认加载全部页）
- 合并顺序 = 选择顺序，遮罩上显示的序号即最终阅读器里的页顺序
- 图片是**按阅读进度懒加载合并**的：阅读器通过 `onWaitUrlImgs` 反查需要加载的可选项，并发 4 逐个取图，每项加载完按顺序重算图片列表，总页数会随加载动态扩展
- 选中状态按列表 id 缓存在 GM 存储中（选择中未确认存 `pending`、确认后存 `confirmed`），翻页/刷新后会自动恢复（pending 在 `registerItems` 时恢复，confirmed 在再次进入多选模式时恢复）
- 为站点新增多选支持后，需在 [src/index.ts](../../src/index.ts) 的站点注释链接后追加标记（`<sup>合订</sup>` 多作品合并 / `<sup>选页</sup>` 指定页），README 与 docs/index.md 的「支持网站」会在下次构建时由 doc-generator 自动生成对应上标；有专属章节的手动站点则在 README 手动区站名后加 `<sup>`
- 修改完成后运行 `pnpm check` 确保没有 ts、lint 错误
